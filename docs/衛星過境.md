# 衛星過境預報

軌道模式（🛰️ 衛星過境）裡有三塊東西，回答的問題不一樣，別搞混：

| 區塊 | 回答什麼 | 要不要連網 |
| --- | --- | --- |
| 🛰️ ISS 現在飛到哪 | 太空站**此刻**的星下點 | 要 |
| 🎯 哪顆衛星會掃到這片海 | **哪一趟**會掃過畫面中心、幾點到幾點 | 要 |
| 下方的時刻表 | 每天大約幾點過境、規格、一趟掃幅夠不夠寬 | 不用 |

---

## 🎯 哪顆衛星會掃到這片海

### 怎麼用

1. 把地圖移到你關心的那片海（計算以**畫面中心**為目標）。
2. 選時窗：未來 24 小時／3 天／5 天。
3. 按 **開始計算**。約一兩秒出清單。
4. 按任何一列 → 那一趟的**地面軌跡**與**掃描帶**會畫在地圖上。再按一次收起來。

清單每顆衛星先列最早一趟，按「展開更多」看後面的。

### 每一列在講什麼

```
🛰️ SENTINEL-2B                      [光學]
10/18 19:52 – 19:53   約 36 秒
最接近 26.8 浬   解析度 10m   掃幅 157 浬
```

- **時間**：掃描帶涵蓋你那個點的起訖（本地時間，24 小時制）。
- **最接近**：這一趟最靠近你的距離。越小越好——代表你在掃描帶中間。
- **掃幅**：這台感測器一趟掃多寬。

出現 **⚠ 擦邊** 代表你落在掃描帶的最外緣：那裡解析度最差、幾何變形最大，
而且軌道推算本身有誤差，實際上很可能根本沒掃到。別拿擦邊的那趟排作業。

### 算不出來的時候會明講

這幾種狀況**不會**顯示成一片空白：

| 顯示 | 意思 | 你能做什麼 |
| --- | --- | --- |
| ○ 這段時間掃不到這裡 | 算得出來，真的沒過境 | 把時窗拉到 5 天 |
| ⚠ 軌道根數清單裡找不到這顆 | 算不出來，不是沒過境 | 按重算再試 |
| ⚠ 根數壞掉或衛星已脫軌 | 上游資料有問題 | 等下次更新 |
| ⚠ 有 N 組根數這次沒抓到 | 這次下載失敗 | 按重算再試 |

把「抓不到資料」顯示成空白，等於告訴你「這幾天沒有衛星會經過」——
那是錯的，而且你可能拿它決定要不要派船。所以一律分開講。

## 準到什麼程度

### 位置是真的

用 **SGP4**（業界標準軌道推算）加上 **celestrak 的真實軌道根數（TLE）**，
不是示意圖、不是「大概這個方向」。根數每天更新幾次，面板上會顯示這份有多舊。

三天內的推算誤差通常在幾公里內，越往後越大，所以時窗最多只開到 5 天。
根數超過 7 天沒更新會標成「偏舊」。

### 但「掃得到」不等於「會拍」

這點很重要：**算的是幾何**——衛星飛過去的時候，感測器的掃幅涵不涵蓋你那個點。

實際上 Sentinel／Landsat 都有**取像排程**，開闊外海常常不在排程內，
飛過去也不會按快門。排程不是軌道算得出來的，這個面板不會假裝知道。

> **沒驗到**：各任務的實際取像策略與排程內容，App 裡沒有可靠來源可以查證。
> 要確認某一趟是不是真的留下影像，還是得開 Copernicus Browser／
> USGS EarthExplorer 查那一天有沒有那一景（面板最下方有一鍵連結）。

另外掃幅邊緣幾公里內不要當精準值——真正的取像邊界還受衛星姿態影響。

## 技術細節

### 資料怎麼來的

celestrak 沒有送 CORS 標頭，瀏覽器直連會被擋。所以 TLE 由本站自己的
Cloudflare Worker 代抓：`/api/celestrak/{group}`（`worker/index.js`）。

Worker 端做了四件事：群組白名單（不做就是個開放代理）、邊緣快取 6 小時
（celestrak 明確要求不要猛抓）、帶可辨識的 User-Agent、
以及擋掉上游故障時回的 HTML 錯誤頁（那種東西仍然是 HTTP 200，
餵給 SGP4 不會爆炸，只會算出看起來正常但完全錯誤的位置）。

前端另外自己驗 TLE 的模 10 檢查碼，任一行不對就整組丟掉。

### 為什麼不會漏掉窄掃幅的那一趟

低軌衛星對地約 7 km/s，Sentinel-1 掃幅只有 250 km，整趟通過約 35 秒 ——
比合理的掃描間隔還短。但一天全用 4 秒間隔要算 17280 個點，
乘上十幾顆在手機上會卡住。

做法是先粗後細：60 秒掃一遍，判斷門檻放寬成「半掃幅 + 一個粗間隔走過的距離」，
找出可能接近的時段，再只對那幾段用 4 秒重算。
單元測試會把這個結果跟「全程 4 秒細掃」逐趟比對，必須完全一樣。
